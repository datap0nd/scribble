# GitHub QA follow-up — 5 September 2026

Reports: https://github.com/datap0nd/scribble/issues/1 through /8. The reported installed build was 2.0.118.0. These changes produce a new candidate; they do not retroactively change that installation or promote the public update channel.

| Report | Cause and implemented change | Regression evidence |
| --- | --- | --- |
| #2: sample PowerPoint rejected | Explicit sample/synthetic/illustrative/example data in the trusted user instruction now becomes host-supplied evidence and a visible sample-data citation. Source review is told to accept the specification, including compressed values and bounded week ranges. Unsupported numeric values still fail. Hyphenated slide counts are recognized. | User-provided Adoption/Errors values pass, an invented 999 fails; production slide dispatcher and simulated cross-application writers remain covered. |
| #3: invented email facts and old future date | Outlook requests receive the current local clock and factual drafting instructions. Before opening or updating an email, a separate grounding review checks the proposed fields against source evidence; unsupported details return a repair instruction to use placeholders. An unsupported ISO past date in a future plan is rejected deterministically. The same review runs for email drafts initiated from other Office apps and Chrome, before write permission is consumed. | Rejected invented stakeholder count preserves permission and never reaches the destination; historical dates present in sources remain allowed. |
| #4: generic protected-page error | The inspection catch previously classified every scripting exception as a protected page. It now distinguishes restricted schemes, denied access, missing tabs, navigation races, and unknown failures. A destroyed document gets one retry. Diagnostics disclose only the origin, not URL queries or raw errors. | Production inspector executes the bounded retry; denied access stops without retry. Live Chrome connection timed out here, so the particular public Samsung page is not certified. |
| #5: repeated attachment extraction | Each task caches bounded text pages by current-byte SHA-256, extension, and offset. Repeated calls revalidate bytes but reuse extraction. Changed bytes invalidate the cache. Cache hits are visible; timings and source identities are in encrypted task diagnostics rather than the progress signature. | A repeat hits the cache; modifying the same attachment file misses and returns new content. This does not promise that a model will never request the same page twice. Images and cross-task results are not cached by this change. |
| #6: flat legacy XLS | The old path read shared strings without cells. ExcelDataReader 3.9.0 now supplies sheet dimensions, explicit rows/columns, blanks, types, merged ranges, and number formats. Stored formula results are disclosed as potentially stale; formula expressions and Excel-rendered display strings are not claimed. | A synthetic BIFF8 fixture covers multiple sheets, missing middle cells, Arabic/Korean text, a merged heading, numbers, booleans, and a formula row. CI also reads that fixture using the installed DLL. Existing XLSX/XLSB tests remain in the suite. |
| #7: narrow tables | Office panes below 520 px render table rows as labeled cards with wrapping. Wide panes retain tables; source cells remain visible. Ordered lists preserve explicit starting numbers across paragraph breaks. | Actual shared HTML is rendered at 340 px and 900 px; all cells/labels fit and list numbering survives. |
| #8: metadata follow-up continues prior analysis | A conservative metadata-only path uses the locked working-set headers, omits previous analysis and body content, suppresses image prefetch, and exposes no tools. The dispatcher rejects unexposed tools. Mailbox completion no longer forces a content analysis for metadata questions. Explicit attachment-read prohibitions remove and reject that tool; working-set follow-ups can answer from existing evidence without forced rereads. | Exact reported prompt exposes zero tools, omits private bodies and old analysis, completes without body receipts, and rejects attempted reads at the host. Content-analysis prompts continue to expose the normal bounded tools. |

ExcelDataReader documentation and license: https://github.com/ExcelDataReader/ExcelDataReader. The dependency and its MIT notice are included in the installer.

These are production-code changes with automated regression coverage, not a claim of perfect local-model behavior. Native Office acceptance on the work PC and the configured Qwen endpoint, the actual three private attachments, and the specific live product-page journey still require retesting. No issue is closed on the basis of simulated Office objects. The existing candidate promotion gate remains in force.
