# Scribble 2.0 delivery

Owner: this implementation task, following the user's 25 September instruction
to redirect delivery and take responsibility. Candidate branch:
`codex/scribble-2-delivery`, based on `1c3dd2e`. This is the integration line;
do not add phase or layout branches. Prior checkpoints remain historical evidence.

The deliverable is a reliable, source-preserving Office draft workflow with an
honest terminal receipt, then evidence of repeatability and supported variation.
Public 2.0.91 remains frozen while the candidate is evaluated.

The immediate dependency order is:

1. Build and deterministic guardrails on the same source.
2. Native acceptance for explicitly supported operations. Chartless revision
   and workbook-derived chart reconstruction are distinct capabilities. A
   chartless receipt must never enable arbitrary native chart edits/copying.
3. The actual request factory, HTTP tool calls, production draft host, journal,
   and terminal task completion through a fake endpoint in disposable Office.
4. Rendered inspection, with reviewer identity recorded honestly. The owner
   has delegated product/design decisions to this task; agent visual judgment
   must be labeled as such, never relabeled as a human verdict.
5. Controlled real-model pilot within the existing authorized budget, then
   three consecutive unassisted passes on a fixed candidate/configuration.
6. Sealed unseen tasks within the declared support scope. Reordered slides,
   varied data and labels must not inherit credit from a fixture-specific pass.

`tests/NativeAcceptance/Test-DeliveryCandidate.ps1` binds offline and native
receipts to one assembly and retains separate model, visual and generalization
gates. It does not equate a successful native helper with a complete product.
It refuses to reuse an existing PowerPoint process. Native execution requires
the current task's desktop-automation permission, as specified by AGENTS.md.

Local compilation now uses a non-admin .NET SDK in
`%LOCALAPPDATA%/ScribbleDeliveryTools/dotnet` and the cached net48 reference
assemblies. This avoids waiting for CI to discover compiler errors; complete
Windows CI still verifies installer construction and release protection.

No new feature scope or cosmetic layout variants until the production route
gate is closed. Fix the first failing stage, preserve its evidence, and rerun
only the checks affected by that change. Every unresolved gate remains explicit.
