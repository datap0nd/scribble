# Hardening implementation status

2026-09-05. This records implementation evidence separately from the audit in `HARDENING_PLAN.md`. It does not certify the entire roadmap or native Office workflows.

## Implemented

- **Generic browser controls:** transparent, zero-sized and clipped native controls retain their semantics and use verified visible labels/checkmarks. Short card names, shadow-root labels, SVG/image alternatives, additional ARIA roles, and full-text query filtering are supported. The tests use ordinary delivery options as well as the historical trade-in example; production code contains no Samsung URL, condition-name dictionary or price fix.
- **Frame actionability:** nested same-origin controls project through frame borders and axis-aligned scaling. Hit tests check the actual click point in every parent, including overlays and shadow-root frame owners. Frame-specific execution uses the same projection. Rotated, skewed and reflected frames report an explicit action limitation. Group labels come from semantic headings and labels, independent of framework/site class names.
- **Native keyboard behavior:** Enter and Space key-down events carry allowlist-derived text, so native activation works without accepting arbitrary caller text. Ranges, spinbuttons, switches and disclosure elements have state-change regressions through the production dispatcher. Native disclosure state also reaches the snapshot and progress fingerprint. Targeted text searches retain matches inside very long paragraphs, and unnamed JavaScript click listeners can be queried by their rendered text.
- **Browser-provided observations:** a fixed read-only broker obtains DOMSnapshot and accessibility data, including JavaScript click listeners. Visible DOM targets must match their observed tag and geometry before entering the normal fresh-ref/actionability/policy path. Closed-root controls are reported as unbound. Unresolved graphic surfaces trigger bounded viewport screenshots for the effective vision model. Canvas and closed-root coordinate clicking are not implemented or claimed to work.
- **Mailbox paging:** scan/match/page counters, original filter metadata and provider-filter/fallback mode are returned. Empty pages advance inside a bounded cancellable host operation. Provider date predicates use widened UTC minute boundaries, followed by exact inclusive checks. The sparse regression crosses 950 nonmatching rows through the actual task controller, with UTC+04 timestamps and a rejected-provider-filter case.
- **Task boundaries:** structured result-envelope parsing replaces substring error detection. Repeated alternating operations are detected; changing scan progress is retained. Fresh requests clear stale recovery banners. Requested slide counts and validated plans cannot disappear behind failed preflight. Shared schema validation runs before application dispatch; the narrow legacy encoded-slide-array case is normalized once.
- **Local diagnostics:** all hosts share task IDs, encrypted rotating stage events, separate raw inference request/response records, schema/request hashes, validation errors, output records and image hashes. The pane retains its recent 128-event tail instead of stopping at 24; its diagnostic ID and effective model are pinned outside that ring. `scripts/Export-TaskDiagnostics.ps1` previews a metadata-only report; `-LocalReplay` reads retained private events locally and never executes tools. Large details explicitly record truncation. This is replay-input inspection, not yet a complete executable transport/application replay engine.
- **Source references:** `read_task_sources` exposes host-issued text spans from captured input, clarification answers, mailbox metadata and successful reads. Slides can cite multiple span IDs; the host resolves original text. Unknown IDs fail. Whitespace-normalized quotes and renderer/list ordinals no longer fail factual-number checks. Real unsupported quantities, including on cover slides, still fail. Images read later in a task are retained and can be resolved by the slide writer. Image bytes are not promoted to verified text merely because a model describes them.
- **Slide recovery:** structured field/stage errors identify the failed slide; approved source reviews are reused when their exact payload/model/endpoint identity is unchanged. Review calls use the effective model selected for the request. Exact requested slide counts reject overflow that would silently create extra pages.
- **Research reads:** task-scoped success caching, fragment-normalized fetch identities, retained source IDs, final redirect URLs and correctly resolved relative links. HTTP not-found/access/rate-limit/server errors have distinct guidance. The contradictory instruction to both use and avoid search-engine URLs was removed. Outlook still does not transmit private mailbox content to public search.
- **Endpoint checks:** Settings tests real inference against mailbox and slide schemas, nested tables, Unicode, tool-result continuation and structured reviewer rejection using synthetic content. No proposed tool executes during the probe. Optional-control compatibility is keyed by endpoint path plus model. Empty completions and transient inference failures are bounded; repeated empty responses open a short circuit. These checks do not certify vision, streaming, parser configuration, native applications, or general semantic accuracy.
- **Release protection:** CI produces a candidate manifest and installer, retaining browser failure traces. It no longer automatically replaces the public installer. `Test-ReleaseEvidence.ps1` rejects missing native/model evidence or different installer bits; `Publish-ScribbleCandidate.ps1` downloads the exact successful build, checks evidence and preserves the previous public installer before promotion. Evidence must come from actual native acceptance; the validator alone does not establish that the claimed tests ran.

## Remaining gates and work

The development machine has no registered Outlook and no Scribble endpoint settings. The actual user endpoint and a functioning licensed Windows/Office acceptance environment are required for the five critical workflows, forty native handoffs and repeated model runs. No native certification or new continuous release has been claimed.

Still outstanding from the broader roadmap: calibrated OCR/source-image verification, the full staged slide compiler and defect-specific repair controller, provider-neutral public discovery and Chrome research returning evidence to the originating Office task, a shared resumable cross-app handoff protocol, automatic native forty-route acceptance, executable synthetic replay, full serving-configuration/streaming/vision probes, and supported actions for currently unbound visual controls. The generic fixes above deliberately surface these limitations instead of treating missing observations as success.

Browser implementation references: [Chrome DOMSnapshot](https://chromedevtools.github.io/devtools-protocol/tot/DOMSnapshot/), [Chrome accessibility](https://chromedevtools.github.io/devtools-protocol/tot/Accessibility/), [Chrome key dispatch](https://chromedevtools.github.io/devtools-protocol/tot/Input/#method-dispatchKeyEvent), and [Playwright actionability](https://playwright.dev/docs/actionability/). Observation and actionability remain separate checks.
